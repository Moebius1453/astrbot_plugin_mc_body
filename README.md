# astrbot_plugin_mc_body

把 AstrBot 智能体接进 Minecraft 成为真正的伙伴。
实际上算是一个相当勉强的 并且要求在服务器之外还需要一个客户端的项目 重点是尽可能让ai真的扮演玩家而不是实体
要求另外一份客户端也是因为这个 在服务器里面 其身份就是可以被看见 封禁的玩家

## 特性

一个住在 Minecraft 服务器里的 AI 玩家，大脑是 AstrBot：

- 真玩家身份：真的客户端、真的账号，list 里能看到她。能跟你一起挖矿、一起被僵尸追
- 走：Baritone 寻路。给坐标、给玩家名、或者说"最近的箱子"，她自己过去
- 说：用角色的身体在游戏公屏说话。游戏里有人叫她，她听得见，回在公屏（不回 QQ）
- 看：坐标 / 血量 / 饥饿 / 时间天气 / 背包 / 附近有什么怪 / 周边地形和功能方块 / 准星指着什么 / 公屏聊天记录
- 干活：合成（给个物品名，她自己推链、自己找工作台、摆料、收成品）、冶炼、开箱子点格子
- 多步任务：派一件活给她，程序一步步做。进度她自己看得见，随时能喊停
- 保命反射：挨打就还手、血低就跑、卡住就停、饿了或血低就吃 —— 不走模型（等模型反应她已经死了）
- 眼睛：真的截她的游戏画面，交给识图模型转成文字。图片不进她的大脑
- 边走边看：一边寻路一边盯着某个东西 —— 移动和转头不打架

## 快速开始

前提：已部署 AstrBot。Minecraft 服务端一侧需要配套的 KubeJS 桥接脚本（见「服务端侧」）。

1. 把 astrbot_plugin_mc_body 放进 AstrBot 的 data/plugins/，重载插件
2. 面板里填 RCON 地址 / 端口 / 密码。走 SSH 隧道就填 127.0.0.1 / 25575
3. 填 allowed_sender_ids —— 不填的话所有调用都会被拒绝（刻意的，见下）
4. 桥接通了之后，在 QQ 里问她"你在哪"，她会调 mc_state 把坐标报给你

> 注意： allowed_sender_ids 默认是空的，此时所有调用都会被拒绝。
> 这组工具能让游戏里的角色真实移动，不该因为"忘了配"就默认放行。

## 玩法示例

| 你说 | 她做什么 |
|---|---|
| 你在哪？ | 报坐标、血量、维度、正在做什么 |
| 过来 | 走到你旁边（你动，她也跟着动） |
| 去挖点木头 | 寻路过去、开始挖 |
| 做一把木镐 | 自己推链：原木  ->  木板  ->  木棍  ->  镐，自己找工作台、摆料、合成 |
| 帮我把这炉铁烧了 | 走过去、开熔炉、放料放燃料、等烧完、取走 |
| 附近有箱子吗 | 扫周边，报出箱子的坐标 |
| 看前面是什么 | 返回准星那一格的方块和坐标（能穿玻璃看过去） |
| 沿着这条路插火把 | 派一个多步任务，边走边插。背包数量对得上才算数 |
| 别跟着我了 | 急停 |
| 往前走的时候盯着那口箱子 | 一边走一边看同一个坐标，视线一路跟着 |
| （游戏公屏）Nanako 你过来 | 听见了，走到你身边，回在公屏 |

## 工具一览

30 个，分五类。她的能力自我认知 = 这张表 + 状态数据包 ——
程序替她做的事（反射、上行注入）如果不做成工具，在她的自我模型里等于不存在。

### 看（12）

| 工具 | 作用 |
|---|---|
| mc_state | 自己的状态：在线、坐标、血量、饥饿、维度、正在做什么 |
| mc_inventory | 背包：有什么、快捷栏第几格在手上、食物能不能吃、武器能打多少伤害 |
| mc_menu | 当前打开的界面里有什么（箱子 / 工作台 / 熔炉…） |
| mc_threats | 附近有没有怪、多远、什么种类、多少血、是不是正瞄着我 |
| mc_around | 周边概览（两层）：先立即给出地形起伏 + 地表成分 + 有方块实体的设施；后台再把工作台/铁砧/石切机/堆肥桶这类没有方块实体的和露头的矿一并扫出来 |
| mc_where | 某个玩家在哪 —— 自己，或服务器上任何人，附离自己多远 |
| mc_lookat | 准星正指着什么（能穿玻璃看过去） |
| mc_events | 刚发生了什么：挨打、死亡、谁进服退服 —— 按序号增量拉取 |
| mc_journal | 状态日志：自己刚才干了什么，按类别翻 |
| mc_chat_log | 游戏公屏聊天记录：谁说了什么、说话时站在哪 |
| mc_place | 地点簿：记住 / 列出 / 自检 / 忘掉「哪儿是什么」 |
| mc_screenshot | 看一眼周围 —— 截游戏画面交给识图模型转述（慢几秒，640×360） |

### 走（4）

| 工具 | 作用 |
|---|---|
| mc_goto | 走到坐标，或走到「最近的那个某某东西」旁边（不用报坐标） |
| mc_follow | 跟随某个玩家 |
| mc_stop | 急停：取消当前任务 + 撤掉寻路与跟随 |
| mc_baritone_raw | 应急口，透传一条 Baritone 命令 |

### 动（8）

| 工具 | 作用 |
|---|---|
| mc_say | 用角色的身体在游戏里说话 |
| mc_hold | 把快捷栏第 N 格拿到手上 |
| mc_equip | 把身上某样东西放到指定位置：手上 / 副手 / 头盔 / 胸甲 / 护腿 / 靴子 / 背包 |
| mc_use | 用手上的东西：吃东西、喝药水、放方块、射箭 |
| mc_use_on | 右键某个坐标上的方块：放方块、按按钮、开箱子、用墓碑钥匙 |
| mc_click | 点当前界面的第 N 个格子 —— 取东西、放东西、合成，都靠它 |
| mc_attack | 打准星指着的东西 |
| mc_aim | 锁定视线：一直看着某个点，边走边看也可以 |

### 做（4）

| 工具 | 作用 |
|---|---|
| mc_craft | 做东西：给个物品名，她自己推出整条合成链并做完（含自己去找工作台） |
| mc_smelt | 冶炼：把原料和燃料放进熔炉，等它烧完，取走 |
| mc_task | 派她去做一件多步的活。目前有 torch（沿途照明）、farm（收种） |
| mc_task_stop | 扔掉当前任务，回去待命 |

### 打（2）

| 工具 | 作用 |
|---|---|
| mc_stance | 战斗姿态：defend 被动还手 / hunt 主动清怪。打不打由她自己决定 |
| mc_retreat | 主动脱战：立刻停手，朝用户或朝安全方向撤 |

### 不过 LLM 的那部分

挨打就还手、血低就吃、卡住就停 —— 这些不走模型。插件里有一个独立的反射循环
盯着她的血量，默认每秒一次。它和智能体是抢占关系：

```
反射（保命）  >  用户指令  >  当前任务
```

被反射打断的任务是挂起不是取消，危险过去后她自己回来接着做。
任何模块都不许绕过这一层直接下令 —— 否则会出现"她走着走着突然停了，
而任务以为已经走到了"这种事。

> 注意： 动作类工具只能报告「已下发」，不能报告「完成了」。
> 服务端只知道动作发给了玩家的客户端；客户端执行到哪一步，靠 mc_state 复核坐标。

## 常见问题

- 她不动 / 没反应：先 /mcbody 做一次连通性自检。桥不通的话，工具全部会报错而不是假装成功。
- 她"听不见"游戏里说话：上行要满足两条 —— enable_chat_uplink 开着，且 white_session 填了（留空不启动）。
- 她说自己"没有某个能力"：配置里的 enable_wiring_note 管这个。强烈建议开着 —— 实测，
  被问"你能不能感知游戏内聊天"时她会答"我听不见"，因为当时真的没有那个工具，她说得没错。
  凡是程序替她做的事（唤醒注入 / 反射 / 事件流），不做成工具就得在提示词里交代，否则她看不见。
- 工具返回"已下发"，是做完了吗：不是。服务端只知道命令发出去了。用 mc_state 复核坐标。
- 她站着不动挨打：看她手上拿的是什么。她挥的是手上的东西 —— 手上攥着一根线，挥了也没伤害。
- 她血一直不回复：原版自然回血看的是饱食度（要 ≥18），不是"饿不饿"。反射已按"血低"触发进食。
- 她被打死过：反射默认开着，但隧道断了反射就是瞎的（会静默退避）。
  另外建议 gamerule keepInventory true。
- 改完插件不生效：开发目录和 AstrBot 的插件目录是两处，
  光"重载"不算，要先把文件复制过去。排查用哈希比对，别比文件名。

## 配置

### 桥接

| 配置项 | 说明 |
|---|---|
| rcon_host / rcon_port | RCON 地址与端口；走 SSH 隧道时填 127.0.0.1 / 25575 |
| rcon_password | 与服务端 server.properties 的 rcon.password 一致。留空则 MC 工具直接报错 |
| rcon_timeout_seconds | 单条命令超时，默认 10 秒 |

### 授权

| 配置项 | 说明 |
|---|---|
| allowed_sender_ids | 允许调用 MC 工具的发送者 ID 白名单。留空 = 全部拒绝 |

### 聊天上行

| 配置项 | 说明 |
|---|---|
| enable_chat_uplink | 是否启用上行 |
| white_session | 要让哪个会话来听（必填，留空则不启动）。格式 平台实例名:消息类型:会话ID |
| character_name | 角色在游戏里的名字。用来区分"她自己说的"和"别人说的" |
| wake_keywords | 唤醒词。留空 = 永远不唤醒，只攒上下文 |
| poll_interval_seconds | 多久拉一次聊天，默认 2 秒 |
| ambient_context_lines | 没被点名的聊天最多攒多少条 |

### 保命反射

| 配置项 | 说明 |
|---|---|
| enable_reflex | 是否启用防御反射 |
| reflex_interval_seconds | 反射检查间隔，默认 1 秒 |
| hp_low | 血量警戒线：低于它，挨打会立刻触发停止 |
| hp_critical | 血量危急线：低于它，战斗中朝远处跑 |
| flee_distance | 逃跑距离（格） |
| reflex_scan_range | 索敌半径（格） |

### 战斗

| 配置项 | 说明 |
|---|---|
| default_stance | 开局姿态：defend 被动 / hunt 主动清怪 |
| enable_mc_stance_tool | 是否允许她自己在运行中改姿态 |
| owner_player_name | 用户的游戏 ID。脱战时"朝用户跑"要用它找人 |
| retreat_toward | 濒死自动逃跑往哪跑：safe 背离怪 / owner 朝用户 |

### 感知

| 配置项 | 说明 |
|---|---|
| enable_body_state | 每 N 次对话给她附一份状态数据包（坐标/血量/饥饿/时间天气/正在做什么/最近发生了什么） |
| body_state_every | 每几次对话附一次，默认 3（第一次必附） |
| enable_wiring_note | 在数据包末尾附一段「接线说明」。强烈建议开着，见常见问题 |
| enable_sight | 给她眼睛（mc_screenshot） |
| vision_provider_id | 用哪个识图模型，留空 = 自动挑一个视觉模型 |
| client_ssh_host | 游戏客户端在哪台机器上（user@host，要配免密 ssh）。留空则 mc_screenshot 报错 |
| client_container | 跑游戏客户端的容器名 |
| client_sudo_password | 那台机器上 docker 的 sudo 密码（走 stdin，不走命令行） |

### 记忆与任务

| 配置项 | 说明 |
|---|---|
| enable_craft | 是否允许她自己合成 |
| enable_mc_task | 是否允许她派自己去做多步任务 |
| journal_capacity | 状态日志最多攒多少条（只存内存，重载即清空） |
| places_file | 地点簿存哪。留空 = 插件目录下的 data/places.json（这个写磁盘） |

## 安全说明

- 凭证只从配置读，不写进源码
- 授权默认拒绝，在工具边界逐次校验发送者 ID
- 与 RCON 的连接不暴露到公网或局域网，建议一律走 SSH 隧道
- 工具参数在边界做校验（玩家名、坐标、文本都会过滤），不提供任意 RCON 或 shell 权限
- 识图那条路上，图片不进模型 —— 截图在客户端机器上就地转成文字，只有文字回来

## 服务端侧

本插件依赖 Minecraft 那一侧的 KubeJS 桥接脚本 —— 在 [bridge/](bridge/) 目录里：

| 文件 | 去哪 |
|---|---|
| bridge/server/mcbridge_server.js | Minecraft 服务端的 kubejs/server_scripts/ |
| bridge/client/mcbridge.js | 角色客户端的 kubejs/client_scripts/ |
| bridge/launcher/ | 客户端启动器 + 容器镜像（重建环境时才用） |

完整部署步骤（含生效方式和排错）：[bridge/DEPLOY.md](bridge/DEPLOY.md)。

命令契约（RCON 里发的是不带斜杠的裸命令）：

| 命令 | 返回 |
|---|---|
| mcb ping | PONG |
| mcb state | 玩家坐标 / 血量 / 维度等即时数据 |
| （桥不可用时） | MCB_FAIL: <原因> |

## 开发

```
main.py            插件入口、工具定义、授权（_guard）与调用壳（_call）
mcb/               所有实现（纯 Python，跑在 AstrBot 里）
  rcon.py          RCON 客户端 + 桥的薄封装（自己实现，处理粘包/拆包）
  render.py        把数据变成给模型看的文本（只许纯函数）
  reflex.py        保命反射（不过 LLM）
  arbiter.py       仲裁层：谁能写"走"这个通道
  tasks.py         任务层：多步行为串成一个目标
  containers.py    通用容器模板：格子角色 → 索引
  craft.py         合成：规划（纯）+ 执行（点格子）
  smelt.py         冶炼编排
  journal.py       状态日志
  places.py        地点簿
  events.py        事件流 + 背包 diff
  sight.py         截图 → 识图 API → 文字
  uplink.py        聊天上行

bridge/            跑在 Minecraft 那一侧的脚本（**不在 AstrBot 里**）
  DEPLOY.md        怎么部署、怎么生效、怎么排错
  server/          服务端桥（KubeJS）
  client/          客户端桥（KubeJS）
  launcher/        客户端启动器 + 容器镜像
```

工具方法本身仍在 main.py 里（拆出去要动 AstrBot @filter.llm_tool 的继承行为，风险大，暂时不动）。

> 注意： 改完记得两件事：
> 1 插件 .py —— 先跑打桩自检，再把文件复制到 AstrBot 的 data/plugins/
> （开发目录和运行目录是两处，光"重载"不算）
> 2 bridge/ 下的脚本 —— 按 [bridge/DEPLOY.md](bridge/DEPLOY.md) 部署，
> 客户端脚本先 node --check

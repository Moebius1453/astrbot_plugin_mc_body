# Minecraft 身体

本插件必须额外运行一份 Minecraft 客户端，并让该客户端作为玩家加入服务器。仅安装 AstrBot 插件和 Minecraft 服务端不能使用。

通过 AstrBot、RCON、KubeJS 和 Baritone，让智能体控制一个真实在线的 Minecraft 玩家，完成聊天、移动、感知、物品交互、合成和程序任务。角色使用独立客户端，不是服务端生成的 NPC。

当前版本：0.40.0。项目仍处于实验阶段，需要手动配置游戏环境和两端桥脚本，不是安装即可使用的一体化方案。

## 环境要求

| 组件 | 要求 |
|---|---|
| AstrBot | 4.27及以上，低于5.0；已配置支持工具调用的模型 |
| Minecraft | 当前实现面向1.21.1与NeoForge环境 |
| 游戏服务端 | 安装兼容的KubeJS并启用安全隔离的RCON |
| 角色客户端 | 独立运行、能够正常入服，安装兼容的KubeJS和Baritone |
| 两端桥脚本 | 使用本仓库配套版本，分别部署到服务端和角色客户端 |
| 截图识图 | 可选，需要视觉模型，以及当前实现使用的SSH、Docker、虚拟显示和截图环境 |

客户端可以与服务端部署在同一台机器，也可以独立部署，但必须保持运行和网络连接。跨机器访问RCON建议使用SSH隧道，插件不会自动建立或维护隧道。

## 功能

- 游戏聊天接入AstrBot会话，被点名后调用智能体，回复发送到游戏公屏。
- 查询身体状态、背包、菜单、附近实体、地形、设施、聊天和事件。
- 使用Baritone前往坐标、寻找附近设施、跟随玩家和执行受限原生命令。
- 控制视线、快捷栏、装备、物品使用、方块交互和菜单点击。
- 从服务端读取配方并规划合成链，通过配方书摆料，核对产物与背包变化。
- 编排熔炉冶炼、沿途照明和农事任务。
- 通过程序反射处理受伤、进食、逃跑、溺水与卡住状态。
- 使用移动仲裁协调保命、用户指令、战斗、任务和闲逛。
- 提供地点簿、状态日志、空闲扫视和可选截图识图。

## 部署

### 1. 准备游戏环境

先确认角色客户端能够正常加入服务器，客户端与服务端的模组和协议兼容。

服务桥默认控制玩家`Nanako`。使用其他玩家名时，需要同步调整服务桥目标、客户端登录身份和插件的`character_name`，不能只修改面板配置。

仓库内的启动器和容器文件是部署参考，不包含完整游戏实例，也不是通用的正版账号登录启动器。

### 2. 安装两端桥

| 文件 | 部署位置 |
|---|---|
| `bridge/server/mcbridge_server.js` | 服务端实例的`kubejs/server_scripts/` |
| `bridge/client/mcbridge.js` | 角色客户端实例的`kubejs/client_scripts/` |

服务端脚本通过`/reload`加载，客户端脚本必须重启角色客户端后加载。升级时需要同步配套的Python插件与桥脚本，不能长期混用不同协议版本。

部署参考见[桥接部署说明](bridge/DEPLOY.md)。其中启动器和容器命令需要按自己的环境调整。

### 3. 安装AstrBot插件

将本仓库放入AstrBot的`data/plugins/astrbot_plugin_mc_body/`，在面板中配置后重载插件。

| 配置项 | 用途 |
|---|---|
| `rcon_host`、`rcon_port`、`rcon_password` | 连接Minecraft服务端RCON |
| `allowed_sender_ids` | 允许调用工具的发送者ID；留空全部拒绝 |
| `character_name` | 与角色客户端实际玩家名一致 |
| `white_session` | 游戏聊天使用的AstrBot会话UMO；留空不启动聊天上行 |
| `wake_keywords` | 触发游戏聊天唤醒的关键词 |
| `owner_player_name` | 主人游戏名，用于相关位置判断和行为 |

会话UMO格式为`平台实例名:消息类型:会话ID`，可从AstrBot会话管理中获取。若使用人格工具白名单，还需将本插件工具加入该人格的可用工具列表。

### 4. 检查连接

在AstrBot中执行`/mcbody`检查连通性，再让智能体调用`mc_state`与`mc_inventory`。身体在线、客户端状态新鲜后，再尝试移动或交互。

游戏内聊天还需要启用`enable_chat_uplink`，并正确填写会话和唤醒词。

## 使用示例

| 请求 | 能力 |
|---|---|
| 查看坐标和血量 | 查询身体状态 |
| 跟着我 | 跟随指定玩家 |
| 附近有什么箱子 | 查询周边设施 |
| 用现有材料做一把木镐 | 规划材料依赖并执行工作台合成 |
| 向北照明，尝试两处，间隔五格，不挖地 | 启动带路线参数的照明任务 |
| 停止任务 | 取消程序任务并撤销相应路线 |
| 走路时看着指定位置 | 并行控制移动和视线 |

照明工具参数示例：

```json
{
  "task": "torch",
  "rounds": 2,
  "spacing": 5,
  "direction": "north",
  "no_break": true
}
```

`rounds`接受1至32的整数，表示位置尝试次数。`spacing`接受3至32的整数。方向支持`east`、`west`、`south`和`north`。

`no_break`默认关闭，仅限制本次照明任务的Baritone路线，不是全局破坏保护，也不限制保命反射。次数会跨任务抢占恢复累计，但不是严格的物品消耗预算。

## 执行与安全边界

### 动作确认

RCON请求使用唯一标识与动作名匹配响应，无法唯一匹配时拒绝确认，不自动重发动作。服务端响应聚合问题仍可能出现，原始RCON文本接口不具备同等关联保证。

说话路径已支持客户端执行回执，但客户端调用聊天发送成功不等于服务器一定接受该消息。移动、点击和放置尚未统一提供执行完成回执，需要继续核对状态、菜单或世界结果。

### 合成

合成只支持背包和工作台配方，不负责采集缺少的材料。工作台搜索受扫描预算影响，实际搜索范围可能小于请求半径。

配方书摆料后仍核对产物注册名、数量和背包增量。结果未知时不自动回退到逐格摆料，避免重复副作用。合成格已有物品时停止并要求核对。

合成失败后，当前事件的后续Minecraft动作被锁定，并停止程序任务与非保命路线。当前仅明确放行`mc_state`、`mc_inventory`、`mc_stop`和`mc_task_stop`。新事件不继承该锁，也不阻断外部插件或已经在途的工具调用。

### 聊天与运行状态

游戏唤醒使用FIFO队列，模型运行期间继续接收聊天。消费游标和待处理状态保存在插件目录的`data/uplink_state.json`，不要将该文件随代码回滚或删除。

状态中的`[mc:uplink]`显示正在执行、排队和待核对数量，不展示失败消息正文，不自动重跑失败项。长时间掉线、高流量和服务端序号重置仍可能造成聊天遗漏，不保证每条消息恰好处理一次。

### 反射与权限

保命反射优先于用户路线，程序任务可被挂起后恢复。反射依赖客户端、服务端和RCON通道，不保证角色不会受伤或死亡。

不要向模型开放任意RCON或系统Shell权限。RCON使用明文协议，不应暴露到公网或不可信网络。配置文件和日志可能包含凭证或对话内容，发布前应自行检查。

截图识图会将游戏截图传回AstrBot主机，再交给配置的视觉提供商处理。主智能体接收文字描述；使用前应确认图像外发符合自己的隐私要求。

## 验证范围

当前已有定制环境中的真实验收记录：

- 游戏聊天唤醒、忙时追加消息和正常重载后消费恢复。
- 说话执行回执与服务端公屏文本核对。
- 原版背包2×2合成、工作台3×3合成、同配方重复执行和跨配方合成链。
- 合成失败后阻止当前事件继续移动及重试。
- 照明方向和间距参数、移动限制设置切换。

尚未完成干净环境安装验收，也未全面验证模组配方、复杂障碍地形、真实战斗抢占和长期无人看护。已有模块不等于所有组合场景都稳定可用。

## 常见问题

| 问题 | 检查方向 |
|---|---|
| 所有工具都失败 | 检查RCON地址、密码、隧道及两端桥版本 |
| 身体显示离线 | 检查额外客户端是否启动并成功入服 |
| 客户端状态陈旧 | 检查客户端脚本是否加载、上行是否正常 |
| 模型没有某个工具 | 检查人格工具白名单、插件开关和发送者授权 |
| 游戏聊天没有回应 | 检查会话UMO、唤醒词及聊天上行开关 |
| 合成找不到工作台 | 确认工作台位置、实际扫描范围和当前菜单 |
| 修改后不生效 | 确认运行目录文件已同步，按文件类型重载或重启 |
| 失败数量持续增加 | 结合本地日志核对，不要批量重跑旧指令 |
